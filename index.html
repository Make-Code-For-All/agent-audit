    What it checks

    Risky code

    Dynamic code execution, download-and-run commands, credential file access, exfiltration endpoints, persistence tricks, obfuscation, hidden characters and text aimed at AI reviewers.

    Dependencies

    npm and PyPI packages in package.json and requirements*.txt, checked against OSV.dev including its known-malicious list, plus names that look like typos of popular packages.

    Repository signals

    New repositories and owner accounts, sudden star counts, forks, missing licence, committed binaries and secret-looking files.

    How it works

    1
    Paste a link

    Any public GitHub repository, or a link to one branch.

    2
    The whole repository is read

    Downloaded once through this site’s scan service and analysed in your browser. Everything in it is treated as hostile text: shown as plain text, never executed.

    3
    Read the report

    Findings grouped by severity, with the file and line for each. The optional deep scan adds Semgrep, secret detection and dependency audits, run on GitHub’s servers; its results are kept for 24 hours and then deleted.

    A clean result is not proof of safety

    The scan cannot see code that is downloaded after install, payloads that activate later, or heavily obfuscated logic. A clean result means nothing was found, not that the repository is safe. Keep using a sandbox and approval prompts.

    Files are read as text. Nothing in the repository is ever run. Deep scan results are deleted after 24 hours.
